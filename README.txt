# Модуль учета отпусков и графиков отпусков

Консольное приложение на C++ 20 для учета отпусков в небольшой компании. 
Проект разработан с применением принципов SOLID и паттернов проектирования. Работа с базой данных MS SQL Server осуществляется через ODBC API.

# Возможности программы
* **Ролевая модель:** разделение прав на «Сотрудник» (только чтение), «Кадровик» (оформление и удаление) и «Админ» (все действия + правка прошедших дат).
* **Безопасность:** пароли хранятся в виде хешей SHA-256.
* **Учет отпусков:** автоматический расчет дней по двум датам, проверка остатков, проверка на пересечение дат.
* **Продление отпусков:** изменение даты окончания с пересчетом дней.
* **Двойное журналирование:** аудит изменений в БД (через триггеры) и журнал событий приложения (текстовый файл).

# Архитектура проекта
Проект разделен на слои (Dependency Inversion):
* **Слой представления (UI):** `KonsolnoeMenu` (ввод-вывод, меню).
* **Слой бизнес-логики:** `UchetOtpuskov` (правила учета, проверка прав, расчет остатков).
* **Слой хранения:** Интерфейс `Hranilishche` и его реализация `SqlHranilishche` (ODBC API).
* **Утилиты:** `date` (работа с датами через `<chrono>`), `tekst` (UTF-8), `parol` (SHA-256), `log` (логирование).
* **Модели данных:** `model.h` (структуры `Otdel`, `Sotrudnik`, `Otpusk`, `Polzovatel`).

# Требования
1. Компилятор с поддержкой C++17/C++20 (Visual Studio 2019/2022).
2. Установленный MS SQL Server (Express или Developer).
3. Установленный **ODBC Driver 17 for SQL Server**.
4. Подключенные библиотеки `odbc32.lib` и `advapi32.lib`.

# Инструкция по сборке
1. Клонируйте репозиторий: `git clone https://github.com/ваш-логин/otpusk-module.git`
2. Откройте решение (`.sln`) в Visual Studio.
3. Убедитесь, что в настройках проекта (Компоновщик -> Ввод -> Дополнительные зависимости) прописаны `odbc32.lib` и `advapi32.lib`.
4. Соберите проект (Build -> Build Solution). Исполняемые файлы появятся в папке `Release` (или `x64/Release`).

# Настройка базы данных
В папке `sql` находятся скрипты инициализации. **Обязательные для работы программы:**
* `01_sozdanie_bazy.sql` — создает таблицы (`Otdely`, `Sotrudniki`, `Otpuska`).
* `02_roli.sql` — создает роли БД и выдает права.
* `03_audit.sql` — создает таблицу `Zhurnal` и триггеры для аудита изменений.
* `04_polzovateli.sql` — создает таблицу пользователей и добавляет тестовые аккаунты.

**Опциональные скрипты (для демонстрации):**
* `zapolnenie_proverk.sql` — заполняет базу тестовыми сотрудниками и отпусками.
* `zaprosy_prov.sql` — набор SQL-запросов (JOIN, SUM) для ручной проверки в SSMS.

**Автоматическая установка:**
Вы можете запустить файл `install.bat` из корня проекта. Он спросит имя сервера, создаст `server.txt`, выполнит обязательные скрипты и предложит добавить тестовые данные.


# Тестирование
Для проверки логики без подключения к реальной БД запустите `proverka.exe`. 
Тесты используют мок-хранилище в памяти (`PamyatHranilishche`) и проверяют:
* Логику работы с датами (високосные года, неверные даты).
* Пересечения отпусков.
* Разграничение прав ролей.
* Обработку ошибок при недоступности БД.
При успешном прохождении выводится `Всего проверок: 74. Ошибок: 0.`


# Журналирование
В программе реализована **двухуровневая система логирования**:
1. **Аудит БД (таблица `Zhurnal`):** заполняется через SQL-триггеры при добавлении/удалении записей в `Otpuska`. Нужен администратору БД для отслеживания изменений данных.
2. **Журнал приложения (`zhurnal_programmy.txt`):** пишется на стороне C++ (`log.cpp`). Фиксирует события, которые не доходят до БД: попытки входа, отказы в бизнес-логике (нехватка дней), ошибки подключения к серверу.

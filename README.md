# Модуль учета отпусков и графиков отпусков

Консольное приложение на C++20 для учета отпусков в небольшой компании. Работа с MS SQL Server идет через ODBC API. Пароли хранятся в виде хешей SHA-256, действия фиксируются в журнале базы и в текстовом журнале программы.

# Быстрый старт для нового пользователя

Нужны четыре вещи:

1. Windows 10/11 x64.
2. **Visual Studio 2022 Community** с компонентом «Разработка классических приложений на C++» (компилятор `cl.exe`).
3. **SQL Server** 2019/2022 Express или Developer с проверкой подлинности Windows.
4. **ODBC Driver 17 или 18 for SQL Server** (x64).

> Если SQL Server или драйвер еще не установлены, см. раздел [Установка SQL Server и драйвера](#установка-sql-server-и-драйвера).

Порядок запуска:

```bat
:: 1. Собрать программу. Появятся build\otpusk.exe и build\proverka.exe
build.bat

:: 2. Создать базу OtpuskKompanii, пользователей и (по желанию) демо-данные
install.bat

:: 3. Запустить программу
run.bat
```

Все три файла лежат в корне проекта. Их можно запускать двойным щелчком или из консоли.

`install.bat` спросит имя сервера, выполнит SQL-скрипты, сохранит имя в `server.txt`, прогонит автотесты и предложит сразу войти в программу.

| Логин | Пароль | Роль | Права |
|---|---|---|---|
| `sotrudnik` | `sotrudnik123` | сотрудник | только просмотр списков |

Пароль при вводе не отображается — это нормально. На вход дается три попытки.

Аккаунты создаются скриптом `sql/07_polzovateli.sql`. Пароли демонстрационные, для реальной эксплуатации их нужно заменить (см. [Смена пароля](#смена-пароля)).

# Что умеет программа

* Роли: сотрудник, кадровик, админ.
* Расчет дней отпуска по двум датам, проверка остатка и пересечения дат.
* Продление отпуска с пересчетом дней.
* Аудит изменений в таблице `Zhurnal` через SQL-триггеры.
* Текстовый журнал `zhurnal_programmy.txt` рядом с местом запуска.

# Требования

* **ОС:** Windows 10/11 x64.
* **Компилятор:** Visual Studio 2022 Community (или 2019) с рабочей нагрузкой «Разработка классических приложений на C++». Сборка идет через `cl.exe`, CMake не нужен.
* **СУБД:** MS SQL Server 2019/2022 Express или Developer. Подключение к БД — с проверкой подлинности Windows (`Trusted_Connection`), логин и пароль SQL Server не используются.
* **Драйвер:** ODBC Driver 17 или 18 for SQL Server, разрядность x64. Программа сама пробует драйверы 18, 17, 13 и старый «SQL Server».
* **sqlcmd** — нужен только для автоматической установки через `install.bat`. Ставится вместе с SSMS или отдельным пакетом SQL Server Command Line Utilities. Без него скрипты можно выполнить вручную в SSMS.

# Сборка

```bat
build.bat
```

Скрипт сам находит Visual Studio (`vswhere` или стандартные папки), вызывает `vcvars64.bat` и собирает два файла:

* `build\otpusk.exe` — основная программа;
* `build\proverka.exe` — автотесты.

Флаги: C++20, статическая CRT (`/MT`), библиотеки `odbc32.lib` и `advapi32.lib`. Благодаря `/MT` на другой машине не нужен отдельно установленный Visual C++ Redistributable.

Если `build.bat` пишет, что `cl.exe` не найден:

1. Установите Visual Studio 2022 Community: <https://visualstudio.microsoft.com/ru/vs/community/>
2. В установщике отметьте «Разработка классических приложений на C++».
3. Запустите `build.bat` снова.

Можно собрать и из «Developer Command Prompt for VS 2022»: там `cl.exe` уже в `PATH`, достаточно выполнить `build.bat`.

## Установка базы данных

Автоматически:

```bat
install.bat
```

Что делает установщик:

1. Если `build\otpusk.exe` нет — сначала собирает проект.
2. Ищет `sqlcmd`, драйвер ODBC и проверяет подключение к указанному серверу.
3. Выполняет обязательные скрипты: `01_sozdanie_bazy.sql`, `04_roli.sql`, `05_audit.sql`, `07_polzovateli.sql`.
4. По желанию добавляет демо-данные: `02_zapolnenie.sql`.
5. Сохраняет имя сервера в `server.txt` (в корне и в `build\`).
6. Запускает автотесты и предлагает войти в программу.

**Внимание:** `01_sozdanie_bazy.sql` пересоздает базу `OtpuskKompanii`. Если база уже есть, все ее данные будут удалены.

# Ручная установка через SSMS

Если `sqlcmd` нет, откройте SQL Server Management Studio, подключитесь к серверу и выполните файлы **строго по порядку**:

1. `sql/01_sozdanie_bazy.sql` — создает базу и таблицы.
2. `sql/04_roli.sql` — создает роли БД.
3. `sql/05_audit.sql` — создает журнал и триггеры.
4. `sql/07_polzovateli.sql` — создает пользователей программы.
5. `sql/02_zapolnenie.sql` — необязательные демо-данные.

Затем создайте в корне проекта файл `server.txt` с одной строкой — именем сервера, например:

```text
localhost\SQLEXPRESS
```

Файлы SQL сохранены в UTF-8. В SSMS при открытии выберите кодировку UTF-8, иначе русский текст в данных может отобразиться неверно.

# Если sqlcmd установлен, но install.bat его не видит

Выполните скрипты вручную из командной строки:

```bat
sqlcmd -S localhost\SQLEXPRESS -E -f 65001 -i sql\01_sozdanie_bazy.sql
sqlcmd -S localhost\SQLEXPRESS -E -f 65001 -i sql\04_roli.sql
sqlcmd -S localhost\SQLEXPRESS -E -f 65001 -i sql\05_audit.sql
sqlcmd -S localhost\SQLEXPRESS -E -f 65001 -i sql\07_polzovateli.sql
```

# Запуск

```bat
run.bat
```

`run.bat` при необходимости сам вызовет сборку, проверит наличие `server.txt` и запустит `build\otpusk.exe`, оставив окно открытым после выхода.

Можно запускать и напрямую:

```bat
build\otpusk.exe
```

Имя сервера программа ищет в `server.txt` сначала в текущей папке, затем рядом с `otpusk.exe`. Если файла нет, используется `localhost`. Поэтому запускать лучше из корня проекта (как делает `run.bat`) либо держать копию `server.txt` в `build\` (ее создает `install.bat`).

## Автотесты

```bat
build\proverka.exe
```

Проверяются даты и високосные годы, пересечения отпусков, права ролей, продление, удаление и обработка ошибок хранилища без реальной БД. Ожидаемый результат: `Всего проверок: 52. Ошибок: 0.`


Журнал приложения — `zhurnal_programmy.txt` в папке, откуда запущена программа. Журнал изменений БД — таблица `dbo.Zhurnal`.

## Смена пароля

Пароли хранятся как SHA-256 в верхнем регистре. Для латинских паролей можно обновить хеш прямо в SQL:

```sql
USE OtpuskKompanii;
UPDATE dbo.Polzovateli
SET ParolHash = CONVERT(NVARCHAR(64),
        HASHBYTES('SHA2_256', CAST(N'novyy_parol' AS VARCHAR(50))), 2)
WHERE Login = N'admin';
```

Для паролей с русскими буквами такой запрос не подойдет: программа хеширует UTF-8, а `VARCHAR` в SQL Server использует кодовую страницу базы. Проще оставить пароли латиницей.

## Структура проекта

```text
app/main.cpp          точка входа, подключение и вход
include/              заголовки (модели, интерфейсы, утилиты)
src/                  реализация: бизнес-логика, ODBC, меню, утилиты
sql/                  скрипты создания БД, ролей, аудита, пользователей
tests/proverka.cpp    автотесты на хранилище в памяти
build.bat             сборка (Visual C++)
install.bat           установка и настройка базы
run.bat               удобный запуск программы
README.md             эта инструкция
```

`build/`, `server.txt` и `zhurnal_programmy.txt` — локальные файлы, в Git они не попадают: `build/` создается сборкой, `server.txt` — установщиком.
